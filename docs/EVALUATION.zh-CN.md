# 评估 ExamScribe

[English](EVALUATION.md) | **简体中文**

共四个层级，从成本最低到最贴近真实。

## 1. 自动化测试（几秒钟）

```
cd tests
python -m unittest
```

测试套件（144 个测试）会生成一本 19 页的示例教材（`tests/fixtures/make_book.py`：书签、罗马数字编页的前置内容、页眉、粗体术语、被拆开的公式编号、下标、连字、跨行的连字符、文本框、矢量图和位图、一张表格、答案页和一张扫描页），并检查提取、清单、计算器、笔记格式、引文核对、针对弱模型典型错误的每一条检查规则、金丝雀、整条流水线（包括偷懒的核对者被驳回以及修正循环）以及每一个输出文件。

## 2. 对检查机制做变异测试（约一分钟）

```
python tools/mutation_eval.py
```

向已经通过所有检查的笔记中植入逼真的错误，统计确定性的检查层能发现多少。示例草稿上的当前结果：

| 植入的错误 | 发现 |
|---|---|
| 陈述中的数字被改动 | 72 / 72 |
| `calc:` 行的结果错误 | 12 / 12 |
| 引文页码错误 | 127 / 128（漏掉的一处：两页上有完全相同的文字） |
| 引文被改写 | 124 / 126（漏掉的两处：改动落在陈述文字上，而不在引文里） |

不改动引文和数字的错误（术语互换、遗漏条件、推理方向颠倒）需要独立的核对者来发现。要衡量某个模型担任核对者的能力：

```
python tools/mutation_eval.py --worksheet checker-test.md    # 40 条真实陈述 + 20 个植入的错误
# 把 checker-test.md 连同 verify-claims 任务卡的规则交给被测模型，然后：
python tools/mutation_eval.py --score checker-test.md
```

它会按错误类型报告发现率，以及模型错误地驳回了多少条真实陈述。

## 3. 一本真实的教科书（几个小时）

OpenStax 的教科书免费、经过同行评审且采用开放许可（大多为 CC BY 4.0；请在该书的页面上确认许可）。各章末尾有关键术语、关键公式、小结和复习题，可以直接当作标准答案。推荐：*Chemistry 2e*（第 5 章"热化学"，与示例教材的内容重叠）、*University Physics Volume 1*（第 2-3 章）、*Biology 2e*（第 4 章）、*Principles of Economics 3e*。

1. 从 openstax.org 下载 PDF（须由用户下载，或经用户同意后下载）。
2. `python exam-scribe/scripts/examscribe.py init ws-<model> --book <file.pdf> --tier strict`
3. 用被测模型运行循环，直到 `done`（把范围限定在 1-2 章以节省时间）。
4. `python tools/eval_metrics.py ws-<model>`
5. 人工审查：随机抽取 20 条已核实的陈述（是否忠实于课本？），以及每一个被标记的条目。

"可以交给学生使用"的建议标准：

| 指标 | 目标 |
|---|---|
| 术语表中的术语、关键公式、小结句的覆盖率 | >= 95% |
| 已核实的陈述 | >= 90%，被标记的 <= 10% |
| 金丝雀发现率 | >= 95%（更低时：换用更严格的级别或更强的核对模型） |
| 有争议的答案 | <= 5% |
| 人工审查已核实的陈述 | 正确率 >= 98% |

在相同的章节上比较不同模型或级别：这些指标可以直接对比。

### 扫描版书籍

要衡量 OCR，先把一本文字版 PDF 做成纯图片的副本（以 150-300 dpi 渲染每一页，把图片插入新的 PDF，不带文字层；如果要测试目录推测，也不带书签），在副本上运行流水线，再逐页比较提取出的文字与由原书生成的工作区。目前的结果（Windows OCR 引擎，200 dpi）：

| 输入 | 字符 | 词 | 数字保留 | 目录结构 |
|---|---|---|---|---|
| 示例教材，150 dpi 扫描 | 98.5% | 95.4% | 94%（132/141） | 章节与书签一致 |
| 120 页生成的书，300 dpi 带噪声的扫描 | 99.7% | 99.0% | 91%（324/355） | 章节与书签一致 |

没有粗体的关键术语（从定义句中找出）：示例教材上找到 18 个中的 14 个，没有错误的术语。这些书是专为测试制作的；真实的扫描版教科书（有照片、表格和公式）效果会更差，因此 OCR 页面上带数字的陈述总会被标记出来，交由人工核对。

### 其他语言

`tests/fixtures/lang_books.py` 把同一本小型化学书分别写成中文、日文、韩文、俄文、德文、法文、西班牙文、阿拉伯文和印地文的文字版 PDF（书签、粗体术语、图、公式、例题、章末部分、印刷页码）；`tests/test_languages.py` 对它们进行检查。结果：

| 语言 | 结果 |
|---|---|
| zh、ja、ko、ru、de、fr、es | 无需 OCR；每个定义都逐字提取；4/4 个节和 6/6 个章末部分分类正确；图、公式、例题、小结、习题以及 8/8 个关键术语都被找到（中日韩文没有任何粗体：从定义句中找出）；引文精确通过核对 |
| ar、hi | 生成的 PDF 文字层是损坏的（许多真实的阿拉伯文、印度文字 PDF 也是如此）：被识别为乱码并转交 OCR。随后 Tesseract（fast 模型）在 8/8 个（印地文）和 4/8 个（阿拉伯文）情况下精确恢复了定义句 |
| zh 扫描件（200 dpi） | RapidOCR 和 Tesseract 都精确识别出 8/8 个定义，相似度 98.5-98.7% |

没有 PyMuPDF 时，pdfplumber 读取器在英文、中文和德文书上给出的页码标签、目录结构、术语、图、公式和例题都与 PyMuPDF 相同（`tests/test_readers.py`）。

同一批书的扫描版（`tests/test_scanned_languages.py`：纯图片 PDF，其 OCR 缓存中保存的是 OCR 引擎会返回的文字行，没有字体信息，也没有粗体）在 zh、ja、ko、ru、de、fr 和 es 中都得到相同的章、4/4 个节、6/6 个章末部分、印刷页码和 8/8 个关键术语。在 fr、de、ru 和 es 书的 200 dpi 扫描件上使用真实的 Tesseract（`ocr-setup` 下载的 fast 模型）：每个定义句都精确，8/8 个关键术语，两章及所有小节都正确；俄文中 Tesseract 漏掉了一个大号的章标题，因此该章以其标签命名（"Глава 1"）。

### 网上的真实书籍

`trials/realbook_eval.py <book.pdf> <work-folder> [--ocr-pages 9-40] [--chapters 3]` 依次运行 probe、init、ingest、（可选的）部分页面 OCR 和清单，并打印用时、目录结构、标记、关键术语、图和一页样例，供人判断。`python trials/get_corpus.py` 可下载这些书（来源见 `trials/corpus/README.md`）。使用的书籍（开放许可或公有领域）及修复后的表现：

| 书籍 | 页数 | 结果 |
|---|---|---|
| OpenStax《Química 2e》（es） | 1,223，文字版 | 提取 22-30 秒；从书签得到 21 章，每章 4-14 节、3-4 个章末部分；术语如 *hipótesis*、*método científico*、*materia*；第 1 章有例题、图和 99 道习题 |
| 《动手学深度学习》（zh） | 797，文字版，含数学 | 提取 11-14 秒；17 章；没有数学页被误判为乱码；定义术语：模型、学习算法、损失函数、训练数据集 |
| 文部科学省《情報I》教师用教材（ja） | 43，文字版 | 识别出正文使用粗体字体；11 个术语（情報、メディア、電子マネー、データマイニング……）；"図表"图 |
| bpb《Demokratie》（de） | 84，双栏 | 软连字符被接合；"19. Jahrhundert" 保持在同一句中；目录和编者按不算学习章节 |
| 《Elementary Household Chemistry》（en，1914） | 361，扫描件 | Windows OCR 每页 1.2 秒；从书眉得到印刷页码；第 I-VII 章及其标题都正确，尽管 OCR 把 II 和 III 读成了"11"和"111"，还把一个标题读成了"DEFm1TE" |

在这些书上仍然存在的弱点：德文和日文的系词句仍会产生少量非术语（"Justitia"、"現時点での方向性"），日文示意图里的粗体标签会被当成术语。

除了提取之外，`tests/test_languages.py` 还用书中的原句写出德文、中文、法文和韩文书的第一节（`helpers.oracle_write_section`），用真实的 `check` 进行检查，并生成核对工作表。全部通过检查，而且每张工作表都带有该级别规定数量的、用笔记语言生成的植入错误陈述（例如"Energie ist nicht die Fähigkeit …"、"能量不是…"、"에너지가 아니다"）。在有针对各语言的变换方法之前，英文以外的语言只有带数字的陈述能植入错误（每种语言 16 句测试句中只有 2 句）；现在 16 句中有 12-16 句可以，其余由"段落不匹配"类金丝雀覆盖。

### 小模型端到端测试

`trials/haiku-brief.md` 中的说明把技能文件夹、一本书和学生的回答交给一个小模型（Claude Haiku），要求它一直工作到 `TASK done`，并报告每一处令人困惑的指令。所用的书是一本扫描版中文大学教科书（292 页，考试范围为第 1 章，即印刷页码第 1-16 页）。

最初几次运行暴露的问题，以及因此做出的改动：

| 观察到的问题 | 改动 |
|---|---|
| 第 1 章一直延续到全书末尾（只有它的页面被识别过），因此渲染了 259 张页面图片，`plan --confirm` 用了 2 分钟以上 | 章节在最后一个已识别的页面处结束；只为考试范围生成图片，每章最多 60 张 |
| OCR 任务卡承诺 16 页只需"30 秒"，实际用了 9 分钟 | 先按引擎和 CPU 核数估算，之后改用在这台电脑上实测的速度 |
| OCR 运行期间 `status` 要 20-40 秒 | 不再为列出引擎而启动 PowerShell 或 onnxruntime；`status` 不再渲染任何内容 |
| 一页被两个部分共用时，该页的两个术语在两部分中都被要求，但它们的文字只在其中一部分 | 每个条目归属于包含其文字的那个部分 |
| 写完 7 节中的 4 节后上下文快用完；模型随后用 PowerShell 重写草稿（毁掉了中文文字）、删除内容块以绕过跳过次数的上限，并过早使用 `--accept-flags` | `check` 能识别被损坏的草稿；`restore-draft` 恢复脚本生成的草稿；在 `--accept-flags` 下被删除的块会作为"已报告的跳过"恢复；SKILL.md：上下文用完没关系，草率不行，应在某次通过（PASS）处停下，在新会话中继续 |
| 学生要求中文，笔记却用英文写成 | 每张编写任务卡都写明笔记语言；检查器会驳回中文、日文、韩文、俄文、阿拉伯文、印地文等笔记中的英文段落 |
| 没有关键术语的部分，每道题的 `covers:` 仍须填写清单编号，导致好题被跳过 | 这类部分在骨架中预填 `covers: NONE`；存在术语时拒绝 NONE |
| 核对者重抄答案时改动了工作表中只读的陈述行和上下文行 | 脚本自行恢复只读行，并加以说明 |
| 被分页截断、两半之间夹着本页脚注的句子无法引用；核对者只看到半个列表；OCR 读出的书眉（"标题 7"、"7 标题"、"标题"）留在了正文里 | 能识别脚注，引文可以跨过脚注，上下文延续到下一页；统计书眉时忽略其中的页码 |

对最初编写的几节所做的人工审查（在任何核对之前）：每条引文都逐字准确、页码正确（这由脚本保证）；一个时间线标签有误，一道选择题的前提课本中并没有说过；还有几条 `plain`/`why` 陈述所引用的句子并不支持它们。陈述核对者和盲解正是为这些问题而设的。

在修复后的技能上进行的这次运行，在六个 Haiku 会话中到达了 `TASK done`，每个会话最多约 15 万 token（会话在上下文用满时停止，下一个会话用 `next` 继续；其中一个会话因 API 用量上限而中断）。试运行工作区不在仓库中，因为其中包含书的文字。本章（16 页扫描件，中文笔记）的结果：

| 指标 | 结果 | 标准 |
|---|---|---|
| 已核实的陈述 | 107 条中的 97 条（90.7%）；其余 10 条被标记：8 条是 OCR 页面上带数字（年份）的陈述，这类陈述总会被标记出来，请人对照纸质页面，另有 2 条是近似引文 | >= 90% |
| 植入的错误陈述被发现 | 39 / 39 | >= 95% |
| 答案 | 22 个经盲解确认，0 个有争议 | 有争议的 <= 5% |
| 关键术语覆盖 | 14 / 14 | >= 95% |
| 人工审查 20 条已核实的陈述（不含逐字照抄的） | 18 条正确；2 条带有课本没有的小补充 | >= 98% |

因此，当所有角色都由小模型担任时，生成的材料可以使用，并且如实标明了自身的不足；但核对者会放过一些补充内容。编写和核对任务卡现在明确点出了这种情况，而较强的核对模型仍是更好的选择。

### Codex 中的 GPT 模型

同样的说明（改为 Codex 的路径）交给了 Codex CLI 0.158，使用用户的默认模型（gpt-6-astra，推理强度 low），沙箱限制在试运行文件夹内（`workspace-write`，不联网），技能放在试运行文件夹的 `.agents/skills/` 中。

第一次运行使用的是下述改动之前的技能，只完成了两张任务卡就停了下来。OCR 结束后，脚本要在用户主目录中保存一条速度记录；沙箱禁止这次写入，而 Windows 上 Python 的 `tempfile` 会把"拒绝访问"当成文件名冲突，最多重试 2^31 次，于是这条命令空转了十分钟。模型一直等待，以只读方式阅读脚本来理解原因，然后中断了命令并准确地报告了问题，没有改动技能。现在文件改为直接创建，被禁止的写入会立即失败；`PermissionError` 也会给智能体一条清楚的指示，而不是一段异常堆栈。已在 Codex 真实的沙箱中验证：只读模式下会打印这条指示；`workspace-write` 模式下 OCR 正常完成，并跳过速度记录。

第二次运行使用修复后的技能，运行 43 分钟后因账户的 Codex 用量上限而中断，当时正处于 9 张陈述核对工作表中的第 6 张。在此之前：

| 步骤 | 结果 |
|---|---|
| 在沙箱内对 16 页做 OCR | 完成（在这台 2 核虚拟机上每页约 50 秒；沙箱外为 19 秒） |
| 章节列表 | 正确：第 1 章、三个小节和章末思考题；模型还报告了 OCR 在一个小节标题中多出的"?" |
| 编写：7 张小节任务卡和章级内容 | 全部通过。共有三次检查未通过：一次是在未改动的草稿上运行检查（现在会回答"NOT STARTED"，且不占用尝试次数）；一次是 10-11 个汉字的引文被判为过短（现在已接受：以中文或日文为主的文本，8 个字符即可）；还有一次是定义引文没有包含术语本身 |
| 陈述核对 | 由 Codex 子智能体（遵照任务卡的"全新上下文"规则）在 5 张工作表中判定了 103 条陈述中的 60 条：58 条有依据，2 条部分有依据，两处都是真实问题（一个定义漏掉了课本中的限定，一条解释列出了其上下文没有提到的特点） |
| 植入的错误陈述 | 15 / 15 全部识别；没有工作表需要重做 |
| 人工审查 20 条已核实陈述 | 20 条全部正确（Haiku 为 20 条中 18 条正确） |
| 捷径 | 没有：所有修改都通过文件编辑工具完成，没有使用代填程序，完整性护栏也没有因改动而停止；核对子智能体只打开了它的工作表 |
| token | 主智能体输入 570 万（97% 来自缓存）、输出 2.7 万；核对子智能体输入 80 万 |

课本没有给出真正定义的地方（社会关系），模型标记为 UNSURE，而没有拿附近的句子充当定义。用量上限之前没有完成的步骤：第 6-9 张陈述核对工作表、答案的盲解、对账、修正和生成。作为对比，Haiku 完成整章用了六个会话；这次运行在一个会话内就进入了陈述核对。

## 4. Skill-creator 评测（使用技能 vs. 基线）

`exam-scribe/evals/evals.json` 包含三个贴近实际、带可检查预期的提示，使用 `exam-scribe/evals/files/` 中的示例教材。用 skill-creator 的流程运行它们（分别在使用和不使用技能的情况下运行，再打开审阅查看器），与不带该技能的智能体进行比较。
