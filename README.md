# ExamScribe

**English** | [简体中文](README.zh-CN.md)

An Agent Skill for Codex, Claude Code, the Claude apps and other agents that turns a textbook into exam-prep
material a student can trust:

- **study notes built for recall**: a pretest, then each key term, formula, worked example and figure
  with the book's own definition, a plain-language explanation, common mistakes, and answers that stay
  blurred until the student has tried
- **self-tests** (multiple choice, true/false, numeric, cloze, short answer) whose answer keys were re-solved
  blind by an independent pass
- **Anki flashcards**, Cornell-style **review sheets**, weekly **interleaved practice**, a timed **mock exam**,
  a **cheat sheet**, a **traps** page and, for open-book exams, a **lookup index**
- a **study calendar** (.ics) with spaced reviews counting back from the exam date
- a **verification report** listing exactly what a human should double-check

Input: a PDF (with a text layer or scanned, in any language), EPUB, Markdown or text, or photos of the pages.
Text layers are read directly in seconds; scans and photos are read with OCR, only for the pages on the exam.

Accuracy comes first. Every claim quotes the book with a page number. Scripts check each quote, number and
calculation. A separate checker pass confirms each claim, and planted false claims (canaries) measure whether
that checker is paying attention. Nothing unverified is presented as verified.

It is built to work with **weaker models too**. A script-driven state machine hands out one small task at a
time. Skeletons pre-fill structure and evidence hints, a strict linter explains every problem, attempts are
bounded, and model tiers trade task size for safety. Guardrails also catch the shortcuts agents take (stopping
to report, fill-in scripts, edited checkers). See
[`exam-scribe/references/model-tiers.md`](exam-scribe/references/model-tiers.md).

## Repository layout

```

  SKILL.md                   instructions the model reads
  agents/openai.yaml         display name for Codex
  scripts/examscribe.py      the CLI: init, next, check, status, config, plan, build, ...
  scripts/integrity.json     checksums of the skill's files (the scripts refuse to run when one was changed)
  scripts/examscribe_lib/    ingest, inventory, notes format, linter, calculator, verification,
                             canaries, pipeline, rendering, flashcards, study plan, report
  references/                guides loaded on demand, subject profiles, finished examples
  assets/                    CSS and JavaScript for the study pages
  evals/                     skill-creator eval prompts and the sample book (not packaged)
tests/                       153 unit and integration tests (python -m unittest discover -s tests), incl. text
                             and scanned PDFs in 9 languages generated by tests/fixtures/lang_books.py and
                             regressions from real books (test_realworld.py)

                             (Chinese: docs/EVALUATION.zh-CN.md)
```

## Requirements

Python 3.9+ with `pymupdf`, `markdown-it-py`, `mdit-py-plugins` and optionally `genanki`:

```
python -m pip install -r exam-scribe/requirements.txt
python exam-scribe/scripts/examscribe.py doctor
```

If PyMuPDF cannot be installed, text PDFs are still read with `pdfplumber` or `pypdf` (slower, no figure
pictures, no OCR). Scanned books need an OCR engine: on Windows 10/11 the built-in one is used (nothing to
install); on any computer `python exam-scribe/scripts/examscribe.py ocr-setup --language xx` downloads the
Tesseract language data (1-5 MB; PyMuPDF contains the engine), and `rapidocr_onnxruntime` is the most accurate
choice for Chinese. Microsoft Edge or Google Chrome is optional (PDF export).

## Speed

A PDF with a text layer, in any language, is read directly and never OCR'd. Measured on a 2-core VM (a typical
laptop is faster):

| Book | Step | Time |
|---|---|---|
| 200-page Chinese / Russian text PDF | extraction + inventory | 2.5 s / 1.8 s (about 11 s without PyMuPDF) |
| 640-page text PDF | `probe` / extraction / inventory | 1 s / 3.8 s / 1.1 s |
| 640-page text PDF | `extract` to Markdown | 4.5 s |
| 640-page text PDF | figure and equation pictures for one chapter | 0.4 s (only studied chapters get pictures) |
| 120-page scan (300 dpi) | OCR with the Windows engine, 2 workers | 27 s (4.4 pages/s), 99.7% of characters right |
| 640-page scan, exam = 2 chapters | OCR of just those 32 pages | 6 s |
| 361-page 1914 scan (Internet Archive) | OCR of 32 pages, Windows engine | 39 s (1.2 s per page) |
| 5-page French / German / Russian / Spanish scans | OCR with Tesseract (data from `ocr-setup`) | 4-6 s |
| 292-page Chinese scan, exam = chapter 1 | OCR of its 16 pages with RapidOCR | 5-10 min on this VM (2-5 s per page on a laptop) |

OCR is only for scans and broken text layers; it waits for the intake questions and reads only the pages on the
exam; runs are cached per page and resume after an interruption. The model never reads the PDF itself. See
`exam-scribe/references/ingest.md`.

## Languages

Tested with text PDFs in Chinese, Japanese, Korean, Russian, German, French and Spanish, and with scanned
versions of the same books: chapters, sections, end-of-chapter parts, figures, equations, worked examples,
exercises and key terms are found, and quotes verify.
Notes in German, Chinese, French and Korean pass the linter, and the checkers' attention tests (planted false
claims) are made in the notes' language: negations, opposites and quantifiers for 12 languages, numbers and term
swaps in any language, and an unrelated-passage fallback. Arabic and Hindi PDFs whose text layer is broken are
detected and read with OCR (Tesseract). `init` detects the book's language. Structure words live in
`exam-scribe/scripts/examscribe_lib/lang.py`. Everything the student sees around the notes (page labels, buttons,
instructions, flashcards, the study plan and calendar, the Obsidian notes and the verification report page) is in
the notes' language for Chinese, Japanese, Korean, German, French, Spanish and Russian
(`exam-scribe/scripts/examscribe_lib/ui.py`; other languages get English labels). Command output for the agent stays
in English.

## Tested on real books

Besides generated test books, extraction was checked on real books: five downloaded from the internet
(open-licensed or public domain; sources in [`trials/corpus/README.md`](trials/corpus/README.md)) and a scanned
textbook supplied by a user. Each exposed problems that are now
fixed and covered by regression tests (`tests/test_realworld.py`, `tests/test_scanned_languages.py`):

| Book | Kind | What it exposed |
|---|---|---|
| OpenStax *Química 2e* (Spanish, 1,223 pages) | text PDF, bookmarks | a duplicate automatic introduction; answer-key and contents titles in Spanish |
| *Dive into Deep Learning* (Chinese, 797 pages) | text PDF, maths | maths pages flagged as garbled; "即使" (even if) read as a definition |
| MEXT 情報I teacher's guide (Japanese) | text PDF | body text set in a bold face; clauses and verbs taken for key terms; 図表 captions |
| bpb *Demokratie* booklet (German) | text PDF, two columns | soft hyphens, "19. Jahrhundert" splitting sentences, front matter as study sections |
| *Elementary Household Chemistry* (1914, English) | scan, no page labels | roman chapter numbers misread by OCR, titles in plain capitals, running heads in the margins |
| A Chinese communication-studies textbook (292 pages, supplied by a user) | scan, junk bookmarks | chapter 1 ran to the end of the book when only its pages were read; 第二章 misread as 第一章; OCR time estimates far too low |

## Installing the skill

ExamScribe is a standard Agent Skill (a folder with `SKILL.md`), so any agent that can run Python can use it.
Download or clone this repository, then:

| Agent | How |
|---|---|
| **Codex** (CLI, IDE, app) | `python install.py --codex` copies the skill to `~/.agents/skills/exam-scribe/` (all projects); add `--project <folder>` for `<folder>/.agents/skills/` (one project). Then type `$exam-scribe` or just describe the task |
| **Claude Code** | `python install.py --claude` (`~/.claude/skills/exam-scribe/`), or with `--project <folder>` |
| **Claude apps** (claude.ai, desktop) | upload `exam-scribe.skill` from the [latest release](https://github.com/instl999/exam-scribe/releases/latest) |
| **Other agents** | `python install.py --dest <the agent's skills folder>`, or let the agent read `exam-scribe/SKILL.md` |

`python install.py` alone installs for every agent it finds on the computer. Then install the Python packages once:
`python -m pip install -r <installed folder>/requirements.txt` (`py -3` instead of `python` on some Windows
computers). The release also has `exam-scribe.zip` (the same folder) for agents without an installer.

Then ask something like: *"Here's my chemistry textbook, the exam is on 15 December: make me study notes
for chapters 2 to 4."*

## Using it with GPT models (Codex, ChatGPT)

The same scripts decide what counts as verified under every model: a claim is verified only when the script found
its quote on the cited page and an independent check confirmed it. What differs between models is how much fixing
that takes, and which shortcuts they try. These guardrails are aimed at the ones agents take:

- every card says to start the next card after PASS, instead of stopping to report progress or to ask;
- programs that fill notes or worksheets are forbidden, and the checks look for their traces: a supporting span
  that shares no words with its claim, one span pasted under many claims, a "plain words" field that copies the
  definition;
- before every command the skill compares its own files with `scripts/integrity.json` and the workspace records
  with what the scripts wrote; a hand edit stops the work until `restore` puts the record back, and the report
  lists it;
- file writes that a sandbox forbids fail at once with a clear message (on Windows, Python's temporary files
  could otherwise spin forever inside Codex's sandbox).

Tips: keep the `strict` tier; in Codex the default `workspace-write` sandbox works when the workspace is inside the
project folder; installing packages and `ocr-setup` need network once. A full run with a GPT model in Codex is
described in [docs/EVALUATION.md](docs/EVALUATION.md).

## How it works

```
init (quick file check) -> ingest -> inventory -> intake (exam, formats, scope)
  -> OCR of scanned pages in the scope (if any) -> plan (priorities with reasons)
  for each chapter:
     write each section (skeleton with one block per inventory item, cited claims, calc lines, questions)
  -> write chapter blocks (overview, must-know vs. the book's summary, concept map, comparisons)
  -> verify claims (fresh-context checker + canaries) -> verify formulas -> blind solve -> reconcile
  -> fix what was rejected (bounded rounds) -> build and share the chapter
done -> course index, practice sets, mock exam, cheat sheet, deck, calendar, verification report
```

The model only ever runs `next` (which prints one task card) and `check` (PASS shows the next card, FAIL
lists fixes). All state lives in the workspace folder, so any session, or any model, can continue the work.

## Limitations

- Extraction quality bounds everything. OCR text is accurate for words but slips on digits, signs and
  formulas, so claims with numbers on OCR pages are always marked for checking; formula-heavy books are best
  converted with a math-aware tool first (see `exam-scribe/references/ingest.md`). Doubtful pages are flagged,
  not trusted.
- OCR engines were tested on Windows (Windows OCR for English; Tesseract for French, German, Russian, Spanish,
  Chinese, Hindi and Arabic; RapidOCR for Chinese). On macOS and Linux only Tesseract and RapidOCR apply, and those
  paths are the same code but have not been run there. Tesseract sometimes misses very large title type; the
  chapter label ("Глава 1") then stands for the title and the user confirms the chapter list. Right-to-left text
  (Arabic, Hebrew) extracts less reliably than other scripts.
- The checker is a model. Canaries measure its diligence, but a model that notices canaries and still
  misses real errors is possible: with Claude Haiku as writer and checker, 2 of 20 hand-audited verified claims
  had a small addition the book does not make (an extra qualifier, a wider scope). Use a strong model for checker
  tasks when you can.
- A small model's context fills up after about five task cards; it then stops at a passed card and a new session
  continues with `next` (a 16-page chapter took six Haiku sessions).
- Verification is thorough, so a whole textbook in the strict tier means many small tasks. Limit
  `scope.chapters` to what the exam covers.

## Changing the skill

After editing any file in `exam-scribe/`, run `python tools/make_integrity.py` to record the new checksums (the
scripts refuse to run on a changed skill, and the tests fail until the manifest is current).

This README and the evaluation guide are in English and Chinese (`README.md` / `README.zh-CN.md`,
